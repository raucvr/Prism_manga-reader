# Prism v4 报告（2026-10-23）

这一轮回应了所有者的三个要求：

1. 从 PDF 的表格结构直接读出数据，让图表绑定到核实过的数据上。
2. 仓库要上传到 GitHub 给用户用，整个架构必须自己闭环。
3. 文字既然是后期排版的，要不要加一层 DeepSeek V4 Pro。

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 图表能不能绑定到表格里核实过的数据 | 能。PDF 的表格按页面几何读出，放进"证据账本"，每个格子一个编号。图表的柱子写成 `@T2.r9.c1`，由程序填入原值。读表在没调过的论文上放错位置的格子为 0。最终验证里 95 根柱子有 69 根直接引用格子 |
| 要不要加 DeepSeek V4 Pro | 加，但只当审稿人和翻译，写手留在 Seed。盲评里它找到 79% 的严重问题，Seed 再查一遍只找到 21%；翻译的意思走样从 23 处降到 1 处 |
| 能不能自己闭环、给 GitHub 用户直接用 | 能。核查、测验、补写、画面检查都由流水线自己的模型完成；跑不了的检查写进质量记录并在阅读页提示；打包字体、跨平台启动脚本、只监听本机、账号问题立即停止并说明怎么办；`eval/` 让用户用自己的模型复现评测 |
| 漫画教会了多少 | 4 篇读者模型没见过的新论文：只看图答对 90%（Claude 读者）和 70%（Seed 读者），不看图只有 53% 和 21% |
| 花费和时间 | 每本中英双语漫画 $1.59 到 $2.33，平均 $1.94，约 30 分钟 |

## 1. 证据账本：图表只能引用表格里的格子

### 做法

| 环节 | 做法 | 文件 |
|---|---|---|
| 读表 | 按页面几何读出每张结果表：多层表头、行名、分组标题、标准误差（并入系数，写成 "0.120 (0.012)"）、跨列单元格。每张表给一个置信度，只有 ≥0.90 的表进入账本。纯本地计算，不调用模型。 | `backend/services/pdf_tables.py` |
| 账本 | 把表格附在论文正文末尾，每个格子一个编号，例如 `[T2.r9]   Transformer (big)   c1: 28.4`。剧本、修正、核查、翻译、重排看到的都是同一份。 | `backend/services/ledger.py` |
| 绑定 | 图表里的数值写成 `@T2.r9.c1`，程序填入原值、原文行和表名；台词里也可以引用格子。写成普通数字的柱子，如果和账本某个格子的数值、行名都对得上，也会自动绑定。 | `ledger.bind_board` |
| 检查 | 引用了不存在的格子要修正；一张图只能来自表格的同一列；同一列里最强的其他系统必须出现在图上；收尾清单只给数字全部在讲解格里出现过的结论打勾。 | `storyboarder_v2.lint_v3`、`_honest_recap` |

### 读表准确率

两个提取方案先在 12 篇论文、36 张表上比较，再在 8 篇它们没见过的论文上比较。选中的方案再经过一轮改进，用两组人工对照页面转录的标准答案打分：

| 测试集 | 表格 | 格子 | 正确 | 放错位置 |
|---|---|---|---|---|
| 开发用的 12 篇（含物理、经济学论文） | 36 | 2837 | 100% | 0 |
| 未调过的 8 篇（独立转录） | 27 | 1507 | 89.3% | 0 |
| 未调过的 8 篇，只算置信度 ≥0.90 的表 | 26 | 1346 | 全部正确 | 0 |

缺失的格子都来自一张置信度 0.50 的表，门槛把它挡在账本之外。PyMuPDF 1.28 和 2.0 读出的表格完全一致。

### 一个修正过的误判

"同一列最强的对手"最初把 CoT 表 1 里的 "Codex | + ext. calc"（思维链加外部计算器，属于论文自己的方法）当成了对手。现在账本会把这类行补全成 "Codex | Chain of thought + ext. calc"。另外，这条规则只要求把最强系统放上图作背景，基线由图要支撑的结论决定。

## 2. 要不要加 DeepSeek V4 Pro

结论：加，但让它当审稿人和翻译，写手留在 Seed。

### 核查：同一批剧本，五种核查方式盲评

取 14 份已经定稿、经过两轮 Seed 核查的英文剧本，分别让五种方式再查一遍。独立审稿代理先在不看任何结果的情况下，对照论文列出每份剧本的真实问题，再匿名评判每一条发现。下表是 DeepSeek 真正收到原文的 9 份剧本（94 处问题，14 处严重）：

| 核查方式 | 发现条数 | 准确率 | 找到的问题 | 找到的严重问题 | 改坏 | 每次耗时 | 每次费用 |
|---|---|---|---|---|---|---|---|
| Seed 再查一遍 | 15 | 67% | 10% | 21% | 0 | 29 秒 | $0.018 |
| DeepSeek 高强度思考 | 59 | 92% | 56% | 79% | 0 | 260 秒 | $0.070 |
| DeepSeek 低强度思考 | 70 | 71% | 51% | 79% | 0 | 199 秒 | $0.052 |
| DeepSeek 不思考 | 269 | 12% | 31% | 50% | 5 | 21 秒 | $0.013 |

另外 5 份 CoT 剧本，DeepSeek 一条都没找到。原因见下一节。

### 一个静默漏洞：内容过滤

DeepSeek V4 Pro 在 ModelArk 上会把 CoT 论文里一段普通的常识问答例题误判为违规。接口照样返回 HTTP 200，但 `finish_reason` 是 `content_filter`，内容为空，计 0 个 token。旧代码看到空回复会再发一次"修复成合法 JSON"的请求，DeepSeek 回了 `{"problems": []}`，结果变成"没有问题"。

已修复：

- 内容过滤直接报错。
- 空回复不再修复。
- 核查和翻译的模型被过滤、或者在账号上没开通时，自动改用 Seed，并写进任务的质量记录。

### 翻译：同一份英文，Seed 和 DeepSeek 各译一遍，盲评

| 指标（14 份剧本合计） | Seed | DeepSeek（不思考） |
|---|---|---|
| 评审更偏好 | 4 份（置信度都偏低） | 10 份 |
| 意思走样 | 23 | 1 |
| 说得比英文更绝对 | 45 | 0 |
| 丢掉限定词 | 7 | 0 |
| 术语、名字、道具错误 | 34 | 18 |
| 生硬、翻译腔 | 22 | 50 |
| 残留英文 | 5 | 30 |
| 每份耗时 / 费用 | 46 秒 / $0.012 | 37 秒 / $0.017 |

DeepSeek 更忠实，但更生硬。提示词已加上"科普漫画口吻、术语第一次写中文加英文缩写"。

### 写手为什么不换

全程用 DeepSeek 的冒烟试跑（Attention）：英文剧本 38 分钟、中文 10.5 分钟、文字费 $0.87，生成 18.9 万个 token，大部分是思考过程。Seed 写同一步只要 6 到 10 分钟。DeepSeek 写的剧本数据更多，但语气更像讲课，单个样本也说明不了写得更好。

### 最终分工

| 环节 | 模型 | 说明 |
|---|---|---|
| 读论文、写剧本、修正、补写 | Seed 2.0 Pro | 不变 |
| 摘要拆解的核对、英中文事实核查、中文发现回写英文 | DeepSeek V4 Pro（高强度思考） | 分批并行，先用 1 个 token 的请求把论文放进缓存 |
| 翻译 | DeepSeek V4 Pro（不思考） | 规则检查加修正 |
| 内部测验 | Seed 2.0 Pro，三次评分取中位数 | DeepSeek 不思考时打分不可靠 |
| 画面检查 | Seed 2.0 Pro（视觉） | DeepSeek V4 Pro 不能看图 |

配置写法：`check_model: "byteplus/deepseek-v4-pro-ga-260813?effort=high"`、`translate_model: "byteplus/deepseek-v4-pro-ga-260813"`。没开通 DeepSeek 的账号会自动退回 Seed。

## 3. 闭环与开源

运行时，流水线本来就不依赖 Claude 或人工：剧本、检查、修正、测验、画面检查都由流水线自己的模型完成。这一轮补上了两类缺口。

### 质量闭环

| 缺口 | 修复 |
|---|---|
| 核查跑不了时悄悄跳过 | 每个任务写质量记录（`job.json` 的 `quality`），阅读页顶栏会提示哪些检查没跑 |
| 核查模型和写手同一个，有同样的盲点 | 第二个模型家族核查（见第 2 节） |
| 评测依赖 Claude 会话里的题目和读者 | `eval/`：14 篇论文的固定题目和固定版本，`backend/tools/eval_quiz.py` 用流水线自己的模型做"只看图答题"，附不看图对照 |
| 内部测验和独立读者几乎不相关（r = −0.06） | 固定题目、三次评分取中位数 |

### 别人拿到仓库能不能用

| 问题 | 修复 |
|---|---|
| Windows 和没装中文字体的 Linux 上中文变方框、负号约等号消失 | 打包字体（ChillRound 圆体、Shantell Sans、Atkinson Hyperlegible Next、DejaVu Sans，共 6.0 MB，均为允许再发布的许可），一个字体解析器，数学符号永不丢弃。Linux 无字体容器里渲染结果与 macOS 逐像素一致 |
| Windows 启动脚本是旧版，跑不起来 | `start.ps1` 重写为 `start.sh` 的同款；`start.bat` 一行调用 |
| 局域网和任意网页都能用你的 key 发起付费任务 | 只监听 127.0.0.1；跨站的写请求一律 403；原始模型接口和旧付费接口默认关闭 |
| 模型没开通、欠费、额度用完被当成"繁忙"反复重试 | 识别账号类错误码，立即停止任务并给出中英文处理办法；创建任务前预检 key 和各个文字模型 |
| 依赖漂移（PyMuPDF 2.0 拉进 76 MB 的 onnxruntime，部分平台没有安装包） | 固定版本上限；测试依赖单独放进 `requirements-dev.txt` |
| 前端构建依赖 Google Fonts、Next 14.2.0 有已知漏洞 | 本地字体；升级到 14.2.35；去掉没用到的依赖 |
| 测试依赖本机 `output/` 目录 | 改从固定版本的 PDF 提取 |
| 换角色图后仍画老角色 | 去字副本记录原图校验值，原图变了就不用旧副本 |

## 4. 文字层的其他修复

| 修复 | 效果 |
|---|---|
| 论文放到每次调用的最前面，并带上每个任务的缓存键 | 实测 DeepSeek 输入的 71% 到 77% 命中缓存 |
| 检查"所有结论都已验证"一类的话，以及清单上泄露的画法说明 | 读者在 13 份报告里有 9 份指出过这个问题 |
| 收尾清单只给数字在故事里出现过的结论打勾 | 程序决定，不靠模型自觉 |
| 中文核查的发现回写英文 | 过去 38 处中文发现里有 30 处在英文里早就存在，却没被修正 |
| 翻译规则检查：比英文更绝对、丢掉限定词、音译人名、"蛋挞" | 发现即一次性修正，修正不得引入新数字 |
| 写剧本和读论文的回复解析失败时重新生成一次 | 最终验证里有一篇因此失败（见第 5 节） |
| 长调用改成流式接收；SSL 中断也会重试 | DeepSeek 思考几分钟也不会被判超时 |

## 5. 最终验证

### 怎么测

- 12 篇论文，每篇一本中英双语漫画，12 个任务同时跑。BERT 和 1000 层强化学习两篇修复后各重跑了一次，原因见下文。
- 论文分三组：
  - 新论文 4 篇：2026 年 9 到 10 月发表，晚于所有读者模型的训练数据。
  - 获奖论文 6 篇：NeurIPS 2025 最佳论文 4 篇，ICML 2026 杰出论文 2 篇。
  - 名篇 2 篇：Attention、BERT。
- 读者从没读过论文，只看画好的图，回答固定题。题目覆盖摘要每一句，一题一个事实（`eval/quizzes/`）。同一类读者再不看漫画答一遍（闭卷），衡量它原本就知道多少。
- 两套读者：
  - Claude 独立代理，严格评分。
  - 仓库自带的 `backend/tools/eval_quiz.py`，读者和评分都是 Seed 2.0 Pro，任何用户都能复现。

### 分组结果

| 组 | 篇数 | Claude 看图 | Claude 闭卷 | Seed 看图 | Seed 闭卷 |

| 新 | 4 | 90% | 53% | 70% | 21% |

- 闭卷不是 0，因为题目本身带着摘要的上下文。

### 验证中发现并已修复的问题

| 问题 | 怎么发现的 | 修复 |
|---|---|---|
| BERT 第一次：补写回复把新格子编成新号码，没写 `after`，被悄悄丢弃，补写什么都没改 | 日志和内部测验 | 新号码的格子按插入处理；回复里没有可用的格子就再问一次；仍然没改动就写进质量记录 |
| 1000 层强化学习第一次：剧本回复的 JSON 修复后仍解析失败，整个任务失败 | 任务失败 | 读论文和写剧本两步，回复解析失败时重新生成一次 |
| BERT 第二次：内部测验偶发失败（模型连续两次没回 JSON），没有补写，质量记录也没记 | 日志 | 整套测验失败时再跑一次；仍失败就写进质量记录；错误信息带上回复的开头。用同一份剧本离线重放两次都正常出分 |
| Right On Q：一批事实核查回了空回复，这批格子没查 | 质量记录 | 每批核查失败时再问一次 |
| BERT 的 GLUE 图把表 1 的平均分和正文里的排行榜分数画在一起，两种指标 | 人工看图 | 图里有柱子引用了格子时，不在同一列的数值会被打回 |
| 场景格写"看着柱状图"，画图模型画出没有数值的假图表（送货司机论文两格，扩散记忆论文一格），读者当成了证据 | Claude 读者 | 剧本检查拦下场景格里的图表字眼；送画图模型前改成"看向画面外" |
| 收尾清单的打勾规则和读者的理解不一致：只认图表上的数字，读者在列表板和对话框里看到的数字只得圆点 | 人工看图（Hivemind）、Claude 读者（BERT、1000 层强化学习、送货司机论文） | 讲解格里出现过的数字（对话、旁白、板子、差值徽章）都算；重排时对已有漫画重新计算 |
| 说话的角色没有名字，只能看对话框尾巴猜（12 位读者都指出） | Claude 读者 | 每一格里每个说话角色的第一个对话框都加名字标签，标签自动避开头部、图表和其他对话框 |
| 收尾清单 ✓ 和 • 混用没有说明，标题还写着"已验证结果" | Claude 读者 | 清单底部加图例（"打勾：漫画里展示过 · 圆点：有数字没在故事里出现"）；有圆点时把"已验证"一类的标题和副标题换掉 |
| 差值徽章不说和哪根柱子比；图表角落孤零零一个 "%" | Claude 读者 | 图表底注写明"+2.40 相对 X"和"单位：%" |

改剧本和检查的几项只对新任务生效。下面的确认任务用的就是这版代码，只有最后补上的"白板上的柱子"这条场景规则除外。名字标签、清单图例和打勾、图表底注只改排字，验证用的 14 本已经免费重排（不调用画图模型）。
